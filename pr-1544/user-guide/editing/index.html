Editing¶

Creating features¶

Edit › Create draws new points, lines and polygons into the layer selected in Layers: click once for a point, or click each vertex and double-click to finish a line or polygon (Esc cancels). Delete (Del) removes the selected features across the map's layers. Edit attributes in the attribute table (Ctrl+T): double-click a cell to change it. Data › Data Design (and Data › Fields) adds and deletes fields and calculates a field from an expression; Calculate Geometry (in the attribute table's toolbar) fills a new or existing numeric field with each feature's area, perimeter, length or X/Y coordinate, in the units you choose, for all features or the selected ones. Length and perimeter include feet and miles; area includes square feet (ft2), acres (ac) and square miles (mi2). Every edit is one undo step. Areas, perimeters and lengths measure on the WGS 84 ellipsoid, the same measure as the network tools and the Measure panel (Spatial Join still measures on the sphere). A ring with a full-turn edge, -180° to 180° along a parallel that the ring reaches down one meridian and leaves back up the other (a globe-wide band, or a cap closed along the pole), counts that whole parallel, as long as the ring's turns leave it closed around the globe; an edge from 180° to -180° anywhere else is a seam along the antimeridian (a polygon split there), so a 1° cell written that way is the cell. A ring winding around a pole is measured as the region it traces, where Geoprocessing gives the smaller polar cap.

Undo (Ctrl+Z) and Redo (Ctrl+Y or Ctrl+Shift+Z) restore project changes, not just feature edits; use Cmd instead of Ctrl on macOS. While typing in a text field, those shortcuts undo or redo the typing instead. Saving keeps the undo history; opening or creating a project clears it. Undo does not reverse files already written by an export.

Modifying features¶

The Edit tab's Edit button turns feature editing on or off for the map; with it off, feature creation, geometry changes and attribute edits are disabled. The Editing pane (Settings, Templates, Status, Modify) holds the rest. Its Distance units selector sets the units used for Move and constant elevation. The choice is remembered independently of the live map's measurement units. The entered numbers are interpreted in the selected units when you click Move, Constant or Apply elevation. The current elevation stays in effect while you edit the value or choose units; click Apply elevation to apply the new inputs.

  • Modify: move the selected features by distances east and north, rotate them, scale them, merge them (polygons are unioned), explode multipart features, split a line where you click, and flip line direction. A single point turns and scales on itself, so Rotate and Scale leave points (text graphics included) as they are: with only points selected they change nothing, say so, and add no undo step. Edit › Tools lists every editing tool. Beyond 85.05°, where Web Mercator stops, Move, Rotate and Scale work on the ground: a feature that reaches beyond it, or that the edit would take beyond it, moves rigidly, together with the selected features sharing a vertex with it (their center goes the distance and direction asked, along the ground and across a pole if that's the way, and the rest turn with the world around it), and turns or scales about its own center. Within ±85.05° an edit is made in Web Mercator, as before (where a long move north covers less ground than asked, and Rotate and Scale turn about the middle of the feature's extent), so an edit that just stays within 85.05° and one that just passes it can land far apart. Only the vertices move rigidly: edges stay straight in longitude and latitude between them, so long edges bend, the more so the nearer the pole one end is than the other, and far less for moves north–south than east–west: an edge from 87° to 89° bends 333 m for each kilometer moved east; one from 89.5° to 89.99° bends much more. Add vertices along them first to keep their shape. A moved feature's longitudes run on from where they were written, past ±180° if it crosses there (to 188°, say, rather than −172°), as within ±85.05°; one carried more than halfway around a pole is written within half a turn of where it was. Rotate and Scale use each feature's own center, so selected neighbors sharing a corner can separate at that corner. Right by a pole a move's directions turn quickly with its center's place: a center at the pole takes "east" from the prime meridian (toward 90°E), one a meter away from its own longitude. The whole edit is refused, and nothing changes, when a selected line or polygon edited on the ground reaches a pole (so moving every feature of a world layer fails while Antarctica is selected), spans 180° of longitude or more in one edge, or would be carried onto or around a pole, or when the edit would move a feature more than 10,000 km on the ground or carry a vertex more than 10,000 km from the center it's edited about. A move of no distance leaves features beyond 85.05° as they are. Moving neighbors one at a time, one within ±85.05° and one beyond, can leave their shared corners apart, by about the distance moved times 2·sin(Δλ/2), Δλ being the corner's longitude from the center of the one moved on the ground (a tenth of it 6° away, half of it 30° away): select them together. Split cuts beyond 85.05° where it's asked: where the point or the line reaches beyond it, at the line's point nearest on the ground (once a split has worked out a million distances along segments near the point, a segment counts as near as the nearest point found on it so far, its nearer end at first, and the split says how many lines it cut that way, or left whole when that point was an end).
  • Cut Polygon (Edit › Tools, or the Editing pane): select polygons, then click a line across them and double-click to finish. Each polygon the line crosses from edge to edge is cut into pieces; a zigzag line can make several. The pieces keep the original's attributes. The original row keeps the largest piece, together with any parts of a multipart polygon that the line missed; every other piece becomes a feature of its own, and the pieces end up selected. Holes the line misses stay in the piece around them. A line that stops inside a polygon cuts nothing there; a line end within a centimetre of an edge counts as on it. When the cut succeeds, a notice says how many selected features the line didn't cut (missed in the result). A line that cuts none of them gives an error instead. edit.cutPolygon={"line": {"type": "LineString", "coordinates": [[0.3, -1], [0.3, 2]]}}.
  • Reshape (Edit › Tools, or the Editing pane): select one line or polygon, then draw a line that leaves its edge and comes back to it. For a polygon, the stretch of boundary between the line's first and last crossings is replaced by the line, keeping whichever of the two possible shapes is larger. A hole left wholly outside the new boundary goes with the part reshaped away, and a notice says how many (holesRemoved in the result). A reshape that would make the boundary cross itself, or a hole cross its outer ring, is refused. For a line, the stretch between two crossings is replaced. A drawn line that crosses only once replaces the shorter end, so start on the line and draw out to extend or redirect an end (edit.reshape={"line": …}).
  • Trace (Edit › Features): while drawing a feature, a cut or a reshape, click a point on a line or polygon edge, then another point on the same edge. The sketch follows the edge between them, going the shorter way round a ring; click a point partway to go the other way. Turn on snapping so clicks land exactly on the edge. From scripts, edit.trace={"from": [lon, lat], "to": [lon, lat]} returns the path along the nearest edge passing within the snapping tolerance of both points ("layer" keeps the search to one layer; add "row" to trace a given feature), and how far each point was from the edge (fromOffM, toOffM, in Web Mercator metres, which run longer than ground metres away from the equator).
  • Edit Vertices (Edit › Features): reshape the selected features on the map. Their vertices show as square handles and each edge has a round midpoint handle. Drag a vertex to move it; drag a midpoint, or click an edge, to insert a vertex; click a vertex and press Del to remove it (a line keeps at least two vertices, a polygon ring three). Clicking elsewhere selects the feature there (Shift adds it). Multipart features and polygon holes work the same way, dragged vertices snap when snapping is on, and each move, insertion or deletion is one undo step. Esc finishes. From scripts and the command line, edit.vertex does the same to one vertex and edit.setGeometry (Set Geometry) replaces a feature's whole shape.
  • Feature templates: named default values for new features, made from a selected feature; the Create tool uses the chosen template.
  • Snapping (Edit › Snapping): new and dragged vertices snap to nearby vertices, edges and line ends of visible feature layers at the current scale (magenta marker; graphics and rasters are not targets). Vertices and ends take priority over edges within the tolerance. Snapping starts off; its vertex, edge and end options start on. Both Point features and individual MultiPoint members use the vertex option; they supply neither edges nor line ends. Dragging a Point or MultiPoint member excludes its entire source feature. The tolerance is how near, in screen pixels, a vertex must come to snap (10 by default, 1 to 100): edit.snapping={"on": true, "tolerancePx": 12, "edge": false} (without "on" it toggles snapping, even when other options are supplied). edit.snap={"lon":12.5,"lat":41.9} queries the current snap target without editing a feature.
  • Settings: Show Vertices marks the vertices of the selected features even when Edit Vertices isn't on (edit.settings={"showVertices": true}).
  • Elevation: new features get a z attribute, constant or sampled from a raster surface at the feature's label point; this is not a change to its geometry's coordinates.
  • Ground to grid: a scale factor and rotation applied to entered distances and directions (Move, and edit.traverse, which draws a line or polygon from distances and bearings).
  • Topology: rules (must not overlap, must not have gaps, must not self-intersect, must not have dangles, must be covered by); Validate lists the errors, and clicking one zooms to it. Beyond 85.05° they follow the geometry tools (see Geoprocessing tools, Near the poles).
  • Status: features added, changed and deleted per layer since the last save.

Moving shared polygon vertices¶

Edit › Features › Shared Vertices opts polygon moves into linked editing. It starts off, lasts only for the current app session, and is not saved in projects or preferences. With it on, dragging a polygon vertex moves every polygon vertex in that layer stored at exactly the same original coordinate, including unselected and filtered-out rows, point-only contacts, other polygon parts and holes. Unrelated polygons touching by chance at that point move together too; turn the switch off to move just the source feature. Inserting and deleting vertices, and moving line or point vertices, keep their existing behaviour. Changing the switch cancels a held drag.

The command uses row positions and the same vertex addresses as edit.vertex:

{"layer":"Parcels","row":0,"part":0,"ring":0,"index":3,"lon":12.5,"lat":41.9}

Run these parameters with edit.moveSharedVertex. It returns the source part, ring and index, plus modified: the number of features whose geometry or attributes actually changed. Every matched feature runs through attribute rules and archiving in one transaction; a rejection rolls back the whole edit. A successful command is one undo step. As with edit.vertex, a direct same-position command still runs the rules and records an edit, even if modified is zero. Undo retains cumulative edit counts. Streamed layers require Load All Features first.

This moves coincident vertices, not every shared boundary. For a boundary stored as P–Q on one polygon and P–R–Q on its neighbour, moving Q moves the two stored Q vertices but leaves R in place. It does not remap intermediate vertices, insert missing ones or refuse the edit because vertex densities differ; the two boundaries can separate. There is no tolerance or nearby-coordinate matching. Use the mustNotOverlap and mustNotHaveGaps topology rules, then Edit › Manage Edits › Topology › Error Inspector (validate) (topology.validate) to inspect a coverage.

Distance units in commands¶

edit.move, edit.traverse and constant edit.elevation accept "units": "Feet", "Meters", "Kilometers" or "Miles" (case insensitive). Omitting units keeps the existing metre default. All traverse legs use the command's units. Conversion to metres happens before ground-to-grid corrections and distance limits; stored elevation stays in metres. Feet mean international feet (0.3048 m), independently of the source CRS's units.

For example, edit.move={"dx":500,"dy":0,"units":"Feet"} moves selected features 152.4 metres east.

Data design¶

The Data tab's Data Design pane keeps attributes valid, on every edit (creating, pasting, attribute edits, Calculate Field):

  • Domains: coded values (code=description) or a numeric range for a field.
  • Subtypes: an integer field's codes, each with a name and default values for new features; the layer is symbolized by subtype.
  • Attribute rules: calculations (a field set from an expression on every insert and update) and constraints (a SQL condition every feature must meet).
  • Contingent values: the combinations of values allowed across fields.
  • Archiving: keeps every edit with its time; restore the layer as it was minutes ago.
  • Relationships: link two layers by key fields; Related Data selects the rows related to the selection.

Clipboard and pop-ups¶

Copy (Ctrl+C) and Cut (Ctrl+X) take selected features from one layer: the active layer if it has a selection, otherwise the first layer with selected features. Paste (Ctrl+V) adds them to the layer selected in Layers, matching fields by name and converting values to the destination field types; unmatched fields stay empty. Geometry types must match. Paste Special adds them as a new layer instead. Copied features also go on the system clipboard as GeoJSON, so they can be pasted into another RustGIS window or a text editor, and GeoJSON copied elsewhere pastes into RustGIS. Copy Path copies the selected layer's data source path.

Whole-layer copying is separate: use Copy Layer or Copy Group and Paste Layer in the Layers pane's context menus to preserve symbology and other layer settings, including when moving layers between maps.

Pop-ups (Home › Navigate) choose which layers a click with Explore identifies: the topmost layer under the click, every visible layer, only selectable layers, only the layer selected in Layers, or nothing. The pop-up lists every feature under the click in those layers, overlapping ones included (up to 100): step through them with ‹ ›. The feature shown is the one selected. The magnifier in the pop-up's header zooms to it. Long feature titles and layer names are shortened with an ellipsis to leave room for the header controls; hover over either name to read it in full.

The topmost and visible modes also identify the features of vector tile layers under the click: PMTiles and MBTiles archives and vector tiles added as data (not catalog basemaps or MapLibre styles), beneath the map's own layers. Each shows its tile layer and source layer (firenze › buildings) and its attributes; tile features can't be selected or zoomed to.

They ask WMS layers too (WMS tile layers that are shown and, as far as their service's capabilities say, queryable): RustGIS sends the service a standard GetFeatureInfo request for the point (WMS 1.3.0 or 1.1.1, as in the layer's address), asking for GeoJSON when it offers it, else GML, other XML, plain text or HTML. While it asks, the pop-up says "Asking the map service…". When something else is under the click, it waits up to 4 seconds for every layer asked to answer, then shows the features found and answered together, in drawing order; answers that come later join it as they arrive. When nothing else is, it waits until an answer has features, and closes once every layer asked has answered (or failed) without any. When the service answers with an error in that format (swisstopo's MapServer can't write some of its layers as GeoJSON, but answers them in GML), RustGIS asks again in the next format it offers, and keeps asking that layer in it for the rest of the session. Topmost asks only the highest WMS layer that can be asked at the point (one that covers it and is queryable), and only when it is drawn over the feature found, or nothing was found; its features then take that feature's place. A project doesn't save the request: a WMS layer from a project reads its service's capabilities again on its first click (once for all the map's layers from that service), so until then Topmost takes it as one that can be asked. identify lists the requests in featureInfo, and identify.featureInfo reads an answer (or, on the command line, asks the service and waits).

A tile layer's row in Layers can be clicked to select it, as a map layer's can (map.selectTiles; no map layer is active then, and clicking one ends it). With Selected in Layers, a click on the map then identifies that tile layer alone: a WMS layer is asked as above, and a vector tile layer, archive or MapLibre style lists its features. This works for catalog basemaps and MapLibre styles too, which the topmost and visible modes leave out.

Object annotations¶

The Annotate tab supports boxes (including paddle rotation), circles, freeform polygons and points. All shapes and classes can share one annotation layer. Create New Annotation Layer, choose a class and colour, and choose a shape. Right-click the layer and choose Annotate Features to continue later. The target selector keeps subsequent annotations in that same layer.

  • Point: click to place each point; click an existing point to select it, then drag to move. The selected point's X and Y fields use its stored reference grid.
  • Circle: drag from the centre to the rim. Click to select, drag inside to move, or drag a rim handle to change the radius. A numeric Radius control uses reference pixels or local grid units.
  • Polygon: click successive vertices. Double-click, click the first vertex, press Enter, or choose Finish Polygon to close it. Backspace removes the last draft vertex. Crossing or touching edges are refused. A failed finish keeps the outline so you can correct it and retry. Select a polygon and drag a vertex to reshape it, or drag inside to move the whole polygon.
  • Box: drag to create; use the rotation paddle, side/corner handles and numeric controls below.

Space + drag and middle-drag pan between annotations and during a polygon draft; the wheel zooms. Space is a temporary override: release it to resume the same annotation tool, then click an existing annotation to edit it. A press begun with Space stays navigation through mouse release, even if Space is released first or the pointer moves too little to become a drag. A hand cursor marks navigation; the annotation cursor returns afterward. Hold Alt to draw over an existing annotation. Escape cancels and returns to Pan. Each completed draw or drag is one undo step. Clicking an existing annotation chooses its shape tool.

Click an annotation, then choose Delete Selected Annotation in its controls, or press Delete while annotating. This removes only that object from its layer, preserving the layer, class palette and selections in other layers. Undo restores it. With no single visible annotation selected, the Delete key does nothing in annotation mode. Save Annotations writes the deletion to the GeoJSON.

While annotating, right-click an object to select it and choose Delete Annotation or Change Class. The class submenu uses the layer’s saved class colours, including unused categories. These actions affect only the clicked object and support Undo. Right-clicking empty map space keeps the usual map menu. Save Annotations writes these edits to the companion GeoJSON.

GeoJSON exports points as Point features and the other shapes as Polygon features. Circles are 256-edge polygon approximations; exact centre, radius and frozen reference frame are retained in the versioned _rustgis_shape text property for constrained editing when reopened. This is a circle in the chosen image/local grid, not a geodesic ground-distance circle. The same property retains point and freeform polygon coordinates in their frozen local grid. As with boxes, external geometry edits can invalidate the construction record; ordinary feature editing remains available. Freeform polygons currently support a single outline (3–512 vertices), without holes. Use GeoJSON for a mixed point/polygon layer; formats that only accept one geometry family may refuse it or report conversion losses. For map-based annotation layers, class colours remain project styling. Image-bound GeoJSON also retains its category palette, as described below.

One image and one GeoJSON¶

For image datasets, load a georeferenced .tif or .tiff, select its raster layer, and choose Annotate › Annotate Image. RustGIS creates an annotation layer bound to that TIFF's original pixel grid, or resumes its sibling GeoJSON:

survey_001.tif
survey_001.geojson

Choose Save Annotations to write the associated GeoJSON. This is separate from saving the RustGIS project: saving a project does not automatically overwrite the GeoJSON. Export Features also carries the metadata when the destination is GeoJSON. Supplying the command's optional path exports a one-off copy and refuses an existing unrelated destination. It leaves the layer's association unchanged: later Save Annotations operations still write the original companion GeoJSON. Open the copied GeoJSON with Annotate Image to continue working from that copy.

Select an imported image annotation layer and choose Annotate Image to reconnect its sibling TIFF. The CLI command annotation.openImage also accepts the path of either member of the pair. Discovery first uses the same basename and .tif/.tiff (also uppercase extensions). If none exists, the validated image basename recorded in the GeoJSON is tried in that same folder. Multiple distinct TIFF matches are an error; select the intended loaded raster explicitly. Renaming both files together works: the dimensions, coordinate system and full affine grid must still match. A mismatched or unrelated sibling GeoJSON is refused and left unchanged. Matching filenames identify the pair, but do not prove the pixels are unchanged if an image has been replaced with another image on exactly the same grid.

All new shapes use the bound image grid; the reference chooser is replaced by the filename and original dimensions. This includes rotated/skewed TIFFs: their original six-term affine transform is read before the display reader resamples pixels north-up. Annotation coordinates remain in original image pixels, not the resampled display grid. Full GeoTIFFs with embedded georeferencing and supported coordinate systems are required. Streamed rasters, overviews, unreferenced scans, CRS overrides and subdatasets are refused; export a corrected GeoTIFF first when the source needs a georeferencing override. In the browser, upload the original TIFF, select it and choose Annotate Image, then use Export Features to download the GeoJSON. Sibling discovery and Save Annotations require local filesystem access and are desktop workflows.

Classes, stable category IDs and RGB colours are embedded in the same GeoJSON, including classes with no features. Import Classes… reads the palette from another image annotation GeoJSON without importing its features or changing the target image. It merges by exact name and ID; conflicting identities are errors, and the import is undoable. Recolouring a class preserves its ID. Use a shared imported palette across images to keep dataset category identities consistent. New categories receive the next unused positive ID; sorting the legend does not assign IDs.

Single-file annotation metadata and OBB exchange¶

The collection's rustgis_annotation member contains this versioned metadata (illustrative):

{
  "version": 1,
  "image": {
    "file_name": "survey_001.tif",
    "width": 4096,
    "height": 2048,
    "crs": {"Epsg": 32633},
    "affine": [400000, 0.5, 0, 5000000, 0, -0.5]
  },
  "categories": [
    {"id": 1, "name": "vehicle", "color": [59, 130, 246]}
  ]
}

This is a RustGIS annotation convention using GeoJSON's foreign members, not a native Roboflow or Label Studio import format. Categories borrow COCO's id and name vocabulary and its panoptic RGB colour convention. Other GIS applications can use the geographic features, but may discard collection metadata when rewriting the file. No XML or palette sidecar is needed.

file_name is a basename, never an absolute path or URL. Pixel (0, 0) is the upper-left corner of the original image; pixel centres are at half-integers. Coordinates are continuous/subpixel, x right and y down. affine is in GDAL order:

world_x = affine[0] + x * affine[1] + y * affine[2]
world_y = affine[3] + x * affine[4] + y * affine[5]

World coordinates use image.crs; GeoJSON geometry remains WGS 84 longitude/latitude. Saved CRS values are "WebMercator", "LonLat", {"Epsg": code} or {"Proj": {"proj4": "…", "label": "…"}}. The affine is invertible and may include rotation and skew. Width/height describe the original image, not a view, overview or training chip.

Each feature retains a stable annotation_id and class. Export derives its category_id from the category table. Construction properties are JSON-encoded text strings, with these decoded contents:

Property Required construction fields
_rustgis_box version: 1, frame, center: [x,y], positive width, positive height, clockwise angle in degrees
_rustgis_shape (circle) version: 1, frame, shape: {"kind":"circle","center":[x,y],"radius":r}
_rustgis_shape (polygon) version: 1, frame, shape: {"kind":"polygon","vertices":[[x,y],…]}
_rustgis_shape (point) version: 1, frame, shape: {"kind":"point","position":[x,y]}

frame retains crs, transform (origin_x, origin_y, pixel_width, pixel_height), and image (the construction image name, which may remain a provenance label after a rename; the binding filename identifies the current pair). Image-bound frames additionally retain affine, which takes precedence over transform and must match the binding's original grid. Legacy map-based frames without affine continue to use transform. Circle radii and rectangle dimensions are exact in that grid. Circle geometry is a 256-edge closed polygon approximation; retaining its centre, radius and frame is required to resume circle editing. A polygon outline has 3–512 distinct vertices, without a repeated closing vertex in the construction record. Its GeoJSON exterior ring is closed.

Box features additionally export an obb property containing four ordered [x,y] pixel corners: local top-left, top-right, bottom-right, bottom-left, rotated around the stored centre. These are unclosed corners in the image's downward-y coordinate system, independently of the geographic polygon's winding/start vertex. They are derived from the construction record on each export; editing the derived obb property does not change the box. annotation.obb returns the same per-box exchange properties without writing a file. Its result reports count (returned boxes), total (all annotations) and skipped (annotations without OBB corners). A nonzero skipped count also produces one summary notice for the layer; empty and boxes-only layers produce none. Non-box annotations remain in the source GeoJSON.

For Supervision, collect these corners into data[ORIENTED_BOX_COORDINATES] with shape (N, 4, 2); map stable category IDs to the dense class indices used by the consumer. For YOLO OBB, divide each x by image width and y by image height, then emit the four corners with the target class index. The native annotation GeoJSON remains the editable source.

Coordinates outside the image are retained, not silently clipped. Training conversion must explicitly reject, retain or clip them; clipping may turn a rectangle into a non-rectangle. Circles/polygons do not acquire an OBB automatically, and points need a task-specific policy. COCO detection boxes are axis-aligned: a consumer must explicitly request an enclosing box or segmentation conversion. Stock RF-DETR OBB training compatibility is not implied by preserving OBB annotations. Cropping, tiling or resizing training images requires transforming the pixel coordinates into the corresponding output image grid.

RustGIS validates stored construction against geometry and refuses incompatible external edits or unknown metadata versions. Image annotation layers and their palettes survive project saves. Projects written by this version use format 2; older RustGIS versions must refuse them. Standalone map/layer files containing image metadata also carry a format-2 guard.

Rotated boxes¶

Annotate › New Annotation Layer creates one annotation layer containing multiple classes and opens its annotation controls. Each drag on empty map space adds another box to that same layer. To resume later, right-click the layer and choose Annotate Features, or choose its name in the Annotate tab's layer selector. Editing is enabled automatically.

Choose a reference raster for new boxes. Type a class such as vehicle and click Add Class; use Class colour to change its colour. Existing classes selects a class for subsequent boxes, including classes defined before any boxes are drawn. New classes also receive colours automatically when a box is created. Multiple classes share one layer and appear separately in its legend. Changing a class colour updates every box of that class, while Apply Class to Selected Box changes only the selected box's class. Class names are exported in GeoJSON; for map-based layers, custom colours are retained in a RustGIS project. Image-bound GeoJSON also carries the category palette.

Select a box to see its eight resize handles and its rotation paddle:

  • Drag the paddle to rotate about the centre. Hold Shift to snap to 15-degree steps.
  • Drag a corner or edge handle to resize along the box's own axes. The opposite corner or edge stays fixed; right angles are preserved even when a handle crosses to the other side.
  • Drag inside the selected box to move it. Width, height and clockwise angle can also be entered numerically. Apply Class to Selected Box changes its class.
  • Three-click creation places the start and end of an edge, then the perpendicular height. Hold Alt when starting a box to draw over an existing annotation.
  • Escape cancels an unfinished box or held drag and returns to Pan. Each completed drag is one undo step. Space + drag pans temporarily and keeps the box tool ready; middle-drag also pans and the wheel zooms. Pan / Stop Annotating returns to Pan. Choose Box to continue.

Where the rectangle is exact¶

A raster reference uses the loaded raster's pixel grid, with subpixel precision: x increases right, y increases down, and angle increases clockwise from the image's rightward axis. Resizing and rotation regenerate corners from the centre, dimensions and angle; they do not repeatedly transform the last result. Changing the map view never changes the stored rectangle.

RustGIS currently resamples rotated or skewed source rasters to north-up on import. An annotation on such a raster is exact in that resampled grid, not in the original file's pixels. An unreferenced scan or a reduced-resolution overview cannot be used as a reference. Without a raster, boxes use Web Mercator grid metres, which differ from ground metres away from the equator. The reference transform and coordinate system are saved with each box; moving or removing the reference layer does not change existing boxes.

Box annotation is supported on flat, untilted Earth maps. Boxes crossing the antimeridian or the polar editing limit (85.05° latitude) are refused. A transformed rectangle can look like a quadrilateral in another projection. Export represents its four transformed corners; curved projected edges are not densified, so use this for local object annotations rather than regional footprints.

GeoJSON export and reopening¶

Use Annotate › Export Features (also available under Publish), with a .geojson destination. Each feature is a closed, counterclockwise WGS 84 longitude/latitude Polygon with four corners, its feature ID, a stable annotation_id property, its class, and a _rustgis_box text property containing the versioned construction parameters and reference frame. Other GIS applications can use the polygons without interpreting that property.

Reopen the GeoJSON, select its layer and choose Box on the Annotate tab or Annotate Features in the layer’s right-click menu to resume. Editing is enabled automatically. Keep _rustgis_box intact for constrained editing. RustGIS validates it against the polygon, accepting reversed winding and a different starting corner. If generic vertex edits or another application change the geometry, the box controls refuse to refit it silently; the feature remains available as an ordinary polygon through Edit Vertices. Unknown construction versions are likewise refused by the box editor and remain preserved as feature attributes.

Use GeoJSON or a RustGIS project to retain constrained editing. Shapefile export shortens field names and limits text to 254 bytes, which can truncate the construction record and annotation ID; its exported polygons remain usable, but may no longer be editable as boxes. The exporter reports these truncations. Box recognition also deliberately uses a strict corner match: if a future projection library changes the regenerated corners, use Edit Vertices on the preserved polygon rather than accepting an automatic refit.

The CLI and scripts can create a layer with annotation.newLayer, then use annotation.addBox and annotation.updateBox. annotation.setClass defines class colours and annotation.resume continues an existing layer. Command search lists their full parameters.
